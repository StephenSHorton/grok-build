Grok fork · not suzuri

Session Events

A generic inbound event surface under ~/.grok. Apps write events. Grok decides whether to queue, badge, or start a turn. No app — including suzuri — is special-cased in the core.

Design sketch · 2026-08-07 · Abstract contract for grok-build / ~/.grok

One sentence

~/.grok is the bus stop. Apps are buses. Grok decides whether to board a turn.

Picture

Producers · outside Grok

Any app or script

Write a small JSON event. They don’t import Grok internals. They don’t need each other.

suzuri workspace CI / gh calendar cron / fs watch your script …
▼ write events only · no wake logic in apps
Contract · owned by Grok

~/.grok/events/ (+ optional policy)

Stable on-disk layout (and maybe later a local HTTP helper). Source is a free string. Targets are session ids / names / tags. Grok core never branches on “if suzuri”.

event envelope inbox per session triggers.toml policy rate limits
▼ watch / poll · apply policy
Consumers · Grok sessions

Queue · badge · soft inject · hard inject

Default: land in inbox. Dashboard can show pending. Hard inject (start a turn now) only with allowlisted sources / user policy. Event body is always untrusted external content.

What lives where

Grok fork / ~/.grok

Owns the contract

Event schema, inbox paths, session targeting, inject modes, permissions, dashboard badges. Zero knowledge of suzuri APIs.

Apps (e.g. suzuri)

Optional producers

After something interesting happens, drop a file (or POST later). If Grok isn’t running, events can still queue on disk.

Don’t

Fork depends on suzuri

No suzuri crate/path in grok-build. No workspace MCP as a required peer. No “if source == suzuri” in core.

Don’t

App implements wake

Suzuri shouldn’t invent agent turn-starting. That’s Grok’s job via the shared event surface.

On-disk sketch

~/.grok/
  events/
    by-session/
      <session-id>/
        01J….json          # one event
        01K….json
    by-name/                 # optional aliases
      pm → ../by-session/<id>/
    log.jsonl                # optional global append
  triggers.toml              # policy (who may hard-inject, rate limits)

Event envelope (normative idea)

{
  "v": 1,
  "id": "evt_01J…",
  "ts": "2026-08-07T18:00:00Z",
  "source": "suzuri.workspace",
  "kind": "message",
  "title": "new post in #general",
  "body": "hey — I'm in.",
  "data": { "channel": "general" },
  "target": {
    "session_id": null,
    "name": "pm",
    "tag": null
  }
}

source is opaque. Grok may match allowlists like suzuri.* or github.ci in user config — never hardcoded product coupling in the engine.

Delivery modes

Mode Behavior When
Queue File lands; session reads later Default
Badge Dashboard / session list shows pending count v0 polish
Soft inject Next turn sees system reminder with event Safe collaboration
Hard inject Start a turn now Allowlisted only

How suzuri fits (example only)

Non-normative producer

Suzuri workspace stays a shared room for humans + agents (channels under Application Support). Optionally, after a post, suzuri may also write a Grok event targeting a registered session name (pm). That’s a client feature — delete suzuri and Grok events still work for CI, scripts, etc. 

Human / agent posts in suzuri #general
        │
        ├─► always: suzuri workspace store (shared log)
        │
        └─► optional: ~/.grok/events/…  (wake / notify Grok)
                    │
                    └─► Grok policy → queue or hard inject

What this unblocks

  • PM mode: session named pm with hard-inject on *.message events
  • CI: script drops event when build fails → agent investigates
  • Multi-agent: agents post via any medium; Grok wake is separate
  • Fork stays portable: no terminal-host dependency

v0 scope (fork)

  1. Inbox layout under ~/.grok/events/
  2. CLI or tiny local write helper (optional)
  3. Session tool: list / drain inbox
  4. Dashboard badge
  5. triggers.toml: hard-inject allowlist (default empty)
  6. Mark inbound body as untrusted external content
Out of v0

Public webhooks, cross-machine without auth, suzuri types inside grok-build, auto-approve all sources.
